# Business Tool

Multi-tenant back office for small hospitality businesses. The first user is a bar in Poland, but nothing should be bar- or Poland-specific unless it sits behind an organization setting (country, currency, time zone, tax ID; ADR 0002).

## Layout

- `api/`: Symfony 8.1 + API Platform 5, run in Docker (FrankenPHP + PostgreSQL 17). See also `api/AGENTS.md` for Symfony conventions.
- `frontend/`: pnpm workspace with all JavaScript. Run pnpm commands from here, or from the root with `pnpm --dir frontend …`.
  - `admin/`: admin panel (React 19, Vite, TanStack Router file routes in `src/routes`, TanStack Query).
  - `timeclock/`: mobile-first PWA for employees, with the same stack.
  - `packages/ui`: shared shadcn/ui components. Add new ones from `frontend/` with `pnpm dlx shadcn@latest add <name> -c admin`; they land in `packages/ui/src/components`.
  - `packages/api-client`: `openapi-fetch` client and shared session. `src/schema.d.ts` is generated by `make types`. Never edit it by hand.
- `adr/`: architecture decision records; index in `adr/README.md`, policy in ADR 0000.
- `.github/`: CI workflows and guard scripts.

## Architecture decisions

This file says *how*; the ADRs say *why*. Read `adr/README.md` and the relevant ADRs before proposing anything structural.

- Do not re-propose a decision an ADR accepted or rejected unless its context changed; then write a new ADR that supersedes it.
- Write an ADR (from `adr/template.md`, next free number, row in `adr/README.md`) for: a new technology or library that shapes the code, an integration pattern, module structure, a new row in the Patterns table, a tenancy or security boundary, CI or branching. Not for features that follow existing patterns.
- The ADR lands in the same change as the code that applies it. If it changes a rule in this file, update the rule in the same change and cite the ADR.
- Accepted ADRs are never edited, renamed or deleted: only the `Status:` line (`Superseded by [NNNN](...)`, `Deprecated`) and pointers to paths or section names may change. `make adr-check` (part of `make qa`, and CI) enforces numbering, statuses and the index.

## Backend module structure

The layout follows a layered, module-per-business-context shape (Domain / Application / Infrastructure + Ui) with command and query buses (ADR 0004). PSR-4: `App\` → `api/src/App`, `Ui\` → `api/src/Ui`.

```
src/App/<Module>/
    Domain/
        Model/              entities (attribute-mapped), value objects, enums
        Repository/         <Name>RepositoryInterface (ports)
        Exception/          <Module>Exception base + specific exceptions
        <Port>Interface.php a port that is neither a repository nor a domain service (e.g. TenantContextInterface)
    Application/
        Command/<UseCase>/  <UseCase>Command + <UseCase>Handler
        Query/<UseCase>/    <UseCase>Query + <UseCase>Handler + <Name>View
        EventHandler/       <Action>On<Event> handlers of domain events, own or other modules'
        Job/<UseCase>/      <UseCase>Job + <UseCase>JobHandler: work queued for the jobs worker (ADR 0025)
    Infrastructure/
        Doctrine/Orm/Repository/   repository adapters
        ...                        Doctrine filters/listeners, external clients (KSeF), ...
src/App/Shared/             bus interfaces incl. `JobBusInterface` (Application), event interfaces (Domain), business date/period value objects (Domain/Time), Messenger buses (Infrastructure)
src/Ui/
    Http/<Module>/          <Name>Resource, <UseCase>Input, Provider/, Processor/
    Http/Listener/          request listeners (SelectOrganizationFromHeaderListener)
    Http/Shared/            Ui helpers (CurrentUser, OpenAPI metadata)
    Console/<Module>/       console commands for manual runs; they queue jobs (ADR 0025)
    Scheduler/              the `default` Symfony Scheduler schedule: cron entries that queue jobs (ADR 0025)
    Fixture/                dev data fixtures
```

Reference modules to copy: `App\Organization` + `Ui\Http\Organization` (commands, queries, PATCH), `App\User` + `Ui\Http\User` (query only).

### Patterns

| Situation | Pattern |
|---|---|
| API write | `#[ApiResource]` operation + `Processor` → command bus → handler → aggregate method → repository `add()`/`save()`; then the processor asks the query bus for the View and returns `Resource::fromView()` |
| API read (item or collection) | `#[ApiResource]` operation + `Provider` → query bus → handler → View(s) → `Resource::fromView()` |
| PATCH (merge-patch) | a provider asks the query bus for the View and returns the mutable `Update<Name>Input::fromView()`; API Platform applies the body onto it; then the processor runs as for any write |
| Background or scheduled job | a job (`final readonly`, primitives) in `App\<Module>\Application\Job\<UseCase>\`, queued with `JobBusInterface::dispatch($job, $deduplicationKey)` to the `jobs` transport and run by the `jobs-worker`; its handler orchestrates (query bus, ports, one command per aggregate on the sync command bus). Per organization: implement `OrganizationJobInterface`; the job bus calls `switchTo()` before the handler and `reset()` after. Scheduled: a `RecurringMessage::cron()` entry with an explicit time zone in `Ui\Scheduler\DefaultSchedule` wraps a fan-out job in `ScheduledJob` (the tick only queues it, with its deduplication key) → query bus for ids → one organization job each. HTTP ("run now") and `Ui\Console\<Module>\` commands queue the same job and return (`202`). Jobs are idempotent, safe to interrupt (one flush per unit, progress recorded after it) and have a time budget; expected outcomes (429, rejected credentials) are recorded, not thrown (ADR 0025) |
| Side effect of a write | domain event on the event bus (`EventPublisherInterface`), handled by an `EventHandlerInterface` |
| Current time | the handler injects `Psr\Clock\ClockInterface`, calls `now()` once and passes the moment into the aggregate (`new Organization(..., $createdAt)`, `addMember(..., $now)`); the Domain never reads the clock (ADR 0015) |
| Business date or period ("today", "this month", `?from=&to=`) | `App\Shared\Domain\Time`: `BusinessDate::containing($clock->now(), $timeZone)` for today, `BusinessDate::fromString()` / `BusinessPeriod::fromStrings()` for API `Y-m-d` values, `BusinessPeriod::month()`; `toUtcRange($timeZone)` with the organization's time zone gives `[from, to)` to query UTC timestamps (`>= from AND < to`). Never compute day boundaries by hand (ADR 0017) |
| Transactional e-mail | after the write succeeded (command or event handler): `App\Shared\Application\Mail\TransactionalMailerInterface::send()` with a `TransactionalEmail` (HTML Twig template in `api/templates/email/`, primitives only in the context); it is queued and the worker renders and sends it (ADR 0012) |
| Storing a per-organization secret (KSeF token, …) | `App\Secret` (ADR 0026): the consumer keeps only the secret's id. Its Ui processor first asks its own query whether the write is allowed (so nothing is stored for a refused request), then sends `SetOrganizationSecretCommand` (owners only; encrypted with libsodium under the `SECRETS_ENCRYPTION_KEYS` keyring, replaced in place) and its own command. Responses show metadata only (`GetOrganizationSecretQuery`: whether set, when); the plaintext comes from `RevealOrganizationSecretQuery` in Application code only (Deptrac forbids it in Ui). Plaintext parameters are `#[\SensitiveParameter]` and never logged, put in events or messages; `SecretUnreadableException` means "missing": the consumer records rejected credentials. Rotation: `app:secret:generate-key`, put it first in the keyring, `app:secret:re-encrypt` |
| Calling an external API (KSeF, …) | a port in `Domain`, an adapter in `Infrastructure/<Vendor>/` on a scoped `symfony/http-client`; adapter tests use `MockHttpClient` with responses recorded in `tests/Fixtures/<Vendor>/`, handlers and API tests an in-memory port; tests and CI never reach the network. Country-specific integrations live in their own module (`App\Ksef`), use the business module only through the buses and are enabled by the organization's country (ADR 0002 §3, ADR 0023, ADR 0024) |

### Dependency rules (enforced by Deptrac: `make deptrac`, part of `make qa`)

| From \ To | Domain | Application | Infrastructure | Ui |
|---|---|---|---|---|
| Domain | yes (own and other modules) | no | no | no |
| Application | yes | own module; other modules only through the buses | no (ports only) | no |
| Infrastructure | yes | yes | yes | no |
| Ui | yes (models, enums, exceptions) | yes (buses, Views) | no | yes |

- Domain may use Doctrine mapping attributes and Symfony (Uid, security user interfaces), nothing else from the framework. Application uses no Doctrine and no API Platform.
- Repository port in `Domain/Repository/`, adapter in `Infrastructure/Doctrine/Orm/Repository/`. Application code injects the interface only. A single implementation is autowired by its interface; no alias needed.
- `EntityManagerInterface` never appears in Domain, Application or Ui.

### Rules

- **Entities** (`Domain/Model`): constructor with the required data, no public setters for state with rules, named methods (`addMember()`, `changeSettings()`). Permission rules that depend on the domain (e.g. "only owners and managers change settings") live in the model and throw a domain exception. IDs are UUID v7 passed into the constructor (generated in the Ui processor or the fixture; ADR 0009). Children of an aggregate are created through the root (`Organization::addMember()`).
- **Commands and queries** are `final readonly` with primitive fields (string ids). One command = one aggregate root changed. Command handlers return nothing and throw on failure. Query handlers return Views (or `null` for "not found / not visible"), never entities.
- **Domain exceptions** extend the module's base exception and are mapped to a status in `config/packages/api_platform.yaml` `exception_to_status` in the same change. An unmapped one is a 500. "Not a member" is reported as not found (404), so existence does not leak.
- **Resources** (`Ui/Http/<Module>/<Name>Resource.php`) are `final readonly`, carry the `#[ApiResource]` declaration and a static `fromView()`. They are the response shape; there are no serialization groups (ADR 0005). Every constructor property is required in OpenAPI (`RequiredPropertyMetadataFactory`), and nulls are always serialized.
- **Inputs** (`Ui/Http/<Module>/<UseCase>Input.php`) always carry `#[Assert\*]` constraints; validation happens only here. Prefer `final readonly` with constructor parameters: a parameter without a default is required in OpenAPI, one with a default is optional. Missing or mistyped fields come back as 422 (`collect_denormalization_errors`). Merge-patch inputs are mutable (see Patterns).
- **Providers and processors** never touch repositories or entities directly: they go through the buses. The signed-in user comes from `Ui\Http\Shared\Security\CurrentUser` and is passed as an id.
- **Buses** run without default middleware (no validation, no transaction middleware). Repositories flush in `add()`/`save()`. Command, query and event messages are never routed to a transport. The async paths are Symfony Mailer's own `messenger.bus.mailer` → `async` transport (PostgreSQL), consumed by the `worker` service together with the scheduler (ADR 0012), and jobs: `messenger.bus.job` (default middleware, deduplication, tenant switching) → `jobs` transport, consumed one at a time by the `jobs-worker` service (ADR 0025).
- **Time in tests**: unit tests pass a `MockClock` (or a fixed `DateTimeImmutable`); API and functional tests call `self::mockTime()` (`ClockSensitiveTrait`, in `ApiTestCase`), which the `clock` service, the Foundry factories and the mothers follow (ADR 0015).
- **Job tests**: the `jobs` and scheduler queues are not consumed in tests (`in-memory://`); API tests assert the queued job and its deduplication key, and each schedule has a unit test of its next run times (ADR 0025).
- **E-mail tests** use the mailer assertions of `KernelTestCase`/`WebTestCase` (`assertQueuedEmailCount()`, `getMailerMessage()`); in tests the queue is in memory and `MAILER_DSN` is `null://null`.
- Register each new module in `config/services.yaml` (excluding `Domain/Model/`), in `config/packages/doctrine.yaml` (`mappings` → `src/App/<Module>/Domain/Model`), and map its exceptions. API resources are discovered from `src/Ui`.

## Multi-tenancy (read before adding entities; ADR 0001)

- `Organization` (module `App\Organization`) is the tenant. `User` (module `App\User`) is global. `Membership` links them with a role: `owner`, `manager` or `employee`.
- Clients select an organization with the `X-Organization-Id` header. `Ui\Http\Listener\SelectOrganizationFromHeaderListener` checks membership (403 if not a member) and calls `TenantContextInterface::switchTo()`.
- Members are deactivated, never deleted (`Organization::deactivateMember()`, `Membership::$deactivatedAt`), because history (shifts, paychecks) refers to them. A deactivated membership gives no access: the listener answers 403, and actor checks use `Organization::isActiveMember()`, not `membershipOf()` (ADR 0014).
- Every business entity implements `App\Organization\Domain\Model\TenantAwareInterface` and uses `TenantAwareTrait`:
  - `TenantFilter` (a Doctrine SQL filter, always on) restricts all queries to the current organization. With no organization selected, tenant-aware tables return no rows (secure by default).
  - `TenantAssignListener` sets the organization on persist.
  - Work outside a request touches tenant data only after `TenantContextInterface::switchTo($organization)`: jobs get it from the job bus by implementing `OrganizationJobInterface` (ADR 0025); anything else calls it itself.
- `tests/Functional/Organization/TenantIsolationTest.php` covers the filter and listener through a test-only entity (`tests/Fixtures/Entity/TenantNote`). Every new tenant-aware endpoint also needs an API test showing another organization's data is invisible.

## Backend conventions

- Timestamps are `DateTimeImmutable` stored in UTC. Business dates and periods are `BusinessDate`/`BusinessPeriod`, converted with the organization's time zone, never the server default (ADR 0017); a stored business date is a `DATE` column mapped with `#[ORM\Column(type: 'business_date')]` (ADR 0017, 0022).
- "Now" comes from `Psr\Clock\ClockInterface` (Symfony's `clock` service) in handlers, fixtures and commands, and is passed into entity constructors and methods as a parameter. Domain code never calls `new \DateTimeImmutable()` without an argument, `time()` or `Clock::get()` (ADR 0015).
- Sessions are refresh tokens (`App\User\Domain\Model\RefreshToken`, ADR 0020). Every new way to set or change a password revokes all the user's sessions, as `SetPasswordHandler` does.
- Money: store integer minor units (grosze) with a currency code; never floats (ADR 0010).
- Schema changes go through migrations (`make migration`); read the generated SQL. Tests build the schema from mapping (Foundry `mode: schema`), and `make db-validate` checks that migrations match.
- PHPStan level 8 must pass (`make phpstan`). Fix the types; don't add ignores.

## Backend tests

| Code | Test type | Location |
|---|---|---|
| Entity methods, value objects, enums | PHPUnit unit, no container, no DB | `tests/Unit/<Module>/Domain/` |
| Command, query and job handlers | PHPUnit unit with in-memory repositories implementing the ports (job handlers: a recording command bus) | `tests/Unit/<Module>/Application/` |
| Repository adapters, Doctrine filters, custom queries | functional, with DB | `tests/Functional/<Module>/` |
| API endpoints | `tests/Api/ApiTestCase` (`clientFor($user, $organization)`, `memberWithRole()`): happy path, 422, 404, authorization matrix by role | `tests/Api/<Module>/` |

- Test methods are snake_case sentences starting with `test_it_`.
- Unit tests build objects with the mothers in `tests/Fixtures/` (`UserMother`, `OrganizationMother`); API and functional tests use the Foundry factories in `tests/Factory/`.

## Frontend conventions

- The API returns plain JSON (`Accept: application/json`; ADR 0006). The client is typed with `createClient<paths, "application/json">`.
- Use the generated types by name: a Resource is `components["schemas"]["<shortName>"]` (e.g. `"Organization"`), an Input is `"<shortName>.<InputClass>"` (merge-patch: `"<shortName>.<InputClass>.jsonMergePatch"`).
- Use `unwrap(api.GET(...))` inside TanStack Query `queryOptions`. Include anything organization-specific in query keys, or clear the cache on organization switch (see `frontend/admin/src/components/app-sidebar.tsx`).
- PATCH uses `application/merge-patch+json`.
- Sessions (ADR 0020): the JWT lives 15 minutes (`JWT_TOKEN_TTL`) and `createApiClient` refreshes it silently from the HttpOnly `refresh_token` cookie, so both apps call the API at a same-origin `/api` (never a cross-site API URL). Sign out with `logout(session)` from `@business-tool/api-client`, which revokes the server session, not with `session.signOut()` alone.
- Dates and times from the API are shown in the selected organization's time zone, never the browser's (ADR 0019): `useDateTimeFormat()` (`@business-tool/ui/hooks/use-organization-time-zone`) for instants, and `@business-tool/ui/lib/date-time` for business dates (`"YYYY-MM-DD"`), periods (`{ from, to }`, inclusive), "today", "this month" and durations. Each app provides the zone with `<OrganizationTimeZoneContext>` from `/me`. Never call `toLocale*String()`, `new Date("YYYY-MM-DD")` or `Intl.DateTimeFormat` directly on API data. Month and period filters use `PeriodPicker` (`@business-tool/ui/components/period-picker`).
- Money from the API is integer minor units in the organization's currency (ADR 0010; `/me` → `memberships[].organization.currency`, provided in admin as `<OrganizationCurrencyContext>`). Show it with `useMoneyFormat()` (`@business-tool/ui/hooks/use-organization-currency`) or `formatMoney()` (`@business-tool/ui/lib/money`), and edit it with `<MoneyInput>` (`@business-tool/ui/components/money-input`), which emits minor units. Never divide minor units into a float. The locale comes from `useLocale()` (`@business-tool/ui/hooks/use-locale`): the browser's until the UI language is decided (#21).
- Unit tests (Vitest, ADR 0018) sit next to the code as `*.test.ts`, with `test_it_` names, and run with `TZ=America/New_York`: `pnpm test` in `frontend/` or `make test-frontend`.
- Admin screens are for owners and managers of the selected organization; employees get the "use the timeclock" start page (ADR 0021). Gate with `frontend/admin/src/lib/access.ts`: `beforeLoad: requireCapability("<capability>")` on each business route, `can(role, "<capability>")` for its link and card. No per-page role checks.
- After changing API resources: `make types`, then fix TS errors (`make qa`, or `pnpm typecheck` in `frontend/`).

## CI (ADR 0011)

GitHub Actions in `.github/workflows/`; guard logic in `.github/scripts/`, runnable locally.

| Workflow | Runs on | Checks | Locally |
|---|---|---|---|
| `ci.yaml` | PRs (not ADR/Markdown-only), `main` | API static (composer validate/audit, YAML and container lint, PHPStan, Deptrac); migrations + `schema:validate` + PHPUnit on PostgreSQL 17; frontend typecheck, lint, unit tests (Vitest, ADR 0018), build, committed `routeTree.gen.ts`; `schema.d.ts` matches the OpenAPI export | `make qa`, `make types` |
| `pr-guards.yaml` | every PR | no new suppressions (`@phpstan-ignore`, `ignoreErrors`, baselines, lint/TS disables, skipped tests, Deptrac `skip_violations`), no net drop in tests (PHPUnit methods plus Vitest cases); merged migrations are never edited | `make guards` |
| `secret-scan.yaml` | PRs, `main` | gitleaks on the PR's commits | — |
| `adr-hygiene.yaml` | changes under `adr/` | ADR numbering, statuses, index | `make adr-check` |

- The only way past `pr-guards` is the `intentional-exception` label on the PR, with the reason in the PR description and in a comment next to the suppression.
- CI runs on the runner, not in Docker: when bumping PHP, Node or PostgreSQL in `api/Dockerfile` or `compose.yaml`, bump `.github/workflows/ci.yaml` too.
- Actions are pinned to a commit SHA with the version in a comment. A new CI gate gets a local `make` target or script in the same change.
